# Introduction

Guitar tablature estimation is the problem of converting an audio recording of guitar performance into a symbolic representation that specifies which string and fret are played at each moment in time. This problem is important because tablature is more directly useful to guitarists than pitch-only transcription: it preserves fingering information, supports performance analysis, and can be used in music education, interactive transcription tools, and automatic accompaniment systems. It is also technically difficult. Unlike standard multi-pitch estimation, guitar tablature prediction must resolve instrument-specific ambiguity, since the same pitch can often be played at multiple positions on the fretboard.

Our motivation was to study whether a deep learning system can recover this more structured output reliably from audio alone, and whether adding temporal sequence modeling improves performance beyond a convolution-only baseline. The project is based on the TabCNN formulation and uses GuitarSet, a dataset of recorded guitar performances with aligned annotations. GuitarSet is a useful benchmark because it provides realistic recordings, frame-aligned labels, and a natural held-out-guitarist evaluation setting that tests generalization across players.

The input to our algorithm is a short constant-Q transform (CQT) window extracted from guitar audio. In the main experiments, each example has shape `(192, 9, 1)`, meaning 192 frequency bins over a 9-frame local time context. We then use either a convolutional neural network (CNN) or a convolutional recurrent neural network (CRNN) to output a predicted tablature frame. The output is a `(6, 21)` tensor: one categorical distribution for each of the six guitar strings, where class 0 denotes a non-sounding or muted state and classes 1 through 20 denote fret positions. In other words, the model takes a local spectral representation of guitar audio as input and predicts, for each string, which fret state is active.

This explicit input-output setup matters because the project is not simply predicting pitch classes or note onsets. A prediction can be pitch-correct but still tablature-incorrect if it assigns the note to the wrong string. For that reason, the report evaluates both pitch-level and tablature-level metrics.

The project did not move directly from baseline to final result. Early experiments exposed severe under-prediction and collapse toward the non-sounding class, especially after parts of the training stack were modernized. This forced a diagnostic phase in which model outputs, class frequencies, and data-pipeline behavior were analyzed before architectural comparisons could be trusted. The first substantial CRNN experiments then used a larger bidirectional GRU, after which the design was simplified to a smaller unidirectional GRU that served as the cleaner final comparison point.

The main findings are mixed rather than one-sided. The stabilized CRNN improves pitch recall and pitch F1, suggesting that temporal context helps recover sounding notes more consistently. However, the CNN remains competitive and in some comparisons superior on exact tablature metrics, implying that better pitch tracking does not automatically translate into more accurate string and fret assignment. A second high-level lesson is methodological: training behavior and implementation details are not incidental in this problem, because class imbalance can dominate optimization and distort architectural conclusions.
